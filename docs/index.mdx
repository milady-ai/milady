Milady is now documented from the first thing a user experiences: choosing or discovering a server, then choosing what that server should do.

The core model for the product is:

- `local`, `remote`, and `Eliza Cloud` are **server targets**
- model providers such as `OpenAI`, `Anthropic`, `OpenRouter`, `Ollama`, and `Eliza Cloud inference` are **routing choices**
- the client should connect to a server first, then ask that server how inference, voice, RPC, and deployment are configured

## The Two Docs Surfaces

- This Mintlify site is the **developer and reference** surface.
- The hosted web app at [`/guides`](https://milady.ai/guides) is the **consumer guide** surface.

That split is intentional. The web app should help end users create or connect to an agent. This docs site should explain how the system is built and where the source of truth lives.

## Current Direction

The repo is in an active migration toward:

- chooser-first startup
- a canonical active-server record on the client
- server-owned provider routing behind the gateway
- a smaller bootstrap config and less onboarding-authored runtime state

The live transitional details are documented in [Current Transitional Seams](/reference/transitional-seams).
