This quickstart is written against the current Milady direction:

1. Launch the app.
2. Choose or discover a server.
3. If needed, finish onboarding for that server.
4. Choose a model provider for chat.
5. Start chatting.

## First Launch

On a fresh install, the splash surface should present the server choices first:

- `Create one`
- `Manually connect to one`
- discovered LAN servers such as `Ren` or `Kei`
- `Use Eliza Cloud` only when cloud credentials are available

The important rule is that **server choice comes before provider choice**.

## Create A Local Server

Choose `Create one` when you want Milady to run the server on the current device.

After the local server starts, Milady continues into onboarding so you can:

- name the agent
- choose a style/persona
- choose the model provider for that server
- finish any optional wallet, voice, or connector setup

Use [Create A Local Server](/guides/create-local-server) if you need the longer version.

## Connect To An Existing Server

Choose one of these when the server already exists:

- a discovered LAN entry
- `Manually connect to one`
- `Use Eliza Cloud`

Connecting to a server does **not** force a provider. A remote or cloud-managed server can still use:

- Ollama or another local provider on that host
- direct providers such as OpenAI or Anthropic
- Eliza Cloud inference

## Choose The Provider

After the server is selected, choose the provider for `llm.text`.

That means:

- runtime target and provider are separate
- a local server can use OpenAI or Anthropic
- an Eliza Cloud server can still use a direct provider
- a remote server can use Eliza Cloud inference if that server is configured for it

See [Select A Model Provider](/guides/select-model-provider).

## Get To Chat

Once the server is reachable and onboarding is complete, the app restores or opens the chat surface and keeps the active server in the client’s local startup state.

Today that startup record is stored as:

- `milady:active-server` as the preferred client-side record
- `eliza:connection-mode` as compatibility storage while the migration is still in progress

That compatibility layer is temporary and documented in [Current Transitional Seams](/reference/transitional-seams).
