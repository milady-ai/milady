Milady still has a config file at:

```text
~/.milady/milady.json
```

If you install from npm or Bun, the published npm package name is `miladyai`.

That file is still important, but it should be treated as **bootstrap and durable server config**, not as a dumping ground for every mutable app state.

## Current Storage Model

| Layer | Purpose | Current state |
| --- | --- | --- |
| `milady.json` | bootstrap and local server config | still active |
| client startup state | selected server for the app shell | migrating to `milady:active-server` |
| server database | mutable routing, preferences, runtime state | active but not yet the only source of truth |
| secure storage | API keys, tokens, wallet material | mixed, still being unified |

## Current Source-Of-Truth Direction

These are the canonical routing objects the repo is moving toward:

- `deploymentTarget`
- `linkedAccounts`
- `serviceRouting`

Those separate:

- where the server runs
- what accounts are linked
- which backend handles each capability

## Environment Variables

The active bootstrap variables are:

| Variable | Purpose |
| --- | --- |
| `MILADY_STATE_DIR` | override the state directory |
| `MILADY_CONFIG_PATH` | override the config file path |
| `MILADY_OAUTH_DIR` | override OAuth credential storage |
| `ELIZA_STATE_DIR` | accepted as legacy compatibility fallback |
| `ELIZA_CONFIG_PATH` | accepted as legacy compatibility fallback |

## Client Startup Persistence

The client-side startup flow now prefers:

- `milady:active-server`

The repo still mirrors to:

- `eliza:connection-mode`

That mirror exists only so older startup and reset paths continue to work while the migration finishes.

## What Not To Assume

- Eliza Cloud credentials do **not** imply Eliza Cloud inference
- local runtime does **not** imply a local model provider
- remote runtime does **not** imply a hosted provider
- the config file does **not** need to contain every secret

Use [Current Transitional Seams](/reference/transitional-seams) for the exact compatibility behavior that still exists in code today.
