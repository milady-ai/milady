Discord server doors open with receipts

Botdick's Discord lane finally has a real toolbox: open public links, read HTML / text / PDFs straight from the VPS, write things into knowledge on demand, draw ASCII art into chat, and refuse to follow any URL that points at the server's own LAN. Less pretend-reading, more receipts.

The Discord lane used to live in a soft mode: ping botdick, hope he summarizes a link, watch him hallucinate a PDF he never opened. That gap is closed. There is now an actual fetch path with a real parse layer and a hard refusal for anything that points at the server's own network.

What's new this release

The previous Eliza release shipped the planner, the connectors, and the shape of an action pipeline. What it did not have was a working VPS-side reader for arbitrary URLs. Botdick faked it: he would quote the URL back, sometimes invent a title, and call it done. This release replaces every one of those soft answers with a receipt.

  • Open public links — fetch with a real client, timeout, content-type sniff, and a max-bytes cap. The fetched page comes back as cleaned plain text, not as a guess.
  • Read HTML / text / PDFs — HTML strips down to readable body text, plain text passes through, and PDFs go through pdftotext on the VPS. No more "here is what the PDF probably says."
  • Write things into knowledge — ask botdick to save a note or a URL and it lands in the knowledge plugin as durable context the next planner turn can actually read.
  • ASCII art straight into chat — small art renders inline with the right code-fence handling so Discord doesn't mangle the spacing.
  • Private-network refusal — anything resolving to 10.0.0.0/8, 172.16/12, 192.168/16, link-local, or localhost comes back as a refusal with the reason. The server does not become a bad idea with a URL attached.

How to actually use it

Two shapes cover most of what people want from a Discord agent that can read the web.

Read a page when you want a compact answer

Drop a public URL, ask the question. Botdick fetches, parses, and replies with the page's compact answer plus a link receipt. If the page is gigantic he'll truncate and tell you. If it 404s, he'll quote the status. If it's a PDF, he runs pdftotext on it before answering.

Add something to knowledge when it should be durable

Some things are reference material — a release note, a doc page, a paste of internal context. Tell him explicitly to save it to knowledge. The next planner turn can then read the note as context without re-fetching, which means follow-up questions are answered from memory instead of re-opening the link every time.

The shape of a receipt

Every read or write comes back with a small structured receipt attached: kind, url, bytes, parser, and a summary line. The homepage's events feed mirrors those receipts, so a public chat read is also a public log entry. There is no quiet path.

Why the private-network block is the important one

Web-fetch tools without an SSRF guard turn into a footgun the first time someone in chat pastes http://127.0.0.1:8080/ or some internal admin endpoint. Botdick refuses both DNS-resolved and literal-IP variants and writes the refusal as a public receipt so the attempt is visible. The bot's lane is the public internet, on purpose, with the door to the host's own machine deliberately welded shut.
