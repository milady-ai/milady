# Your first launch

The first time you open Milady, it asks for a name and where the agent should run. First-run setup is voice-driven when your system browser runtime supports speech: Milady speaks the prompt, listens for your answer, and keeps the same text controls on screen if you prefer typing. This page is a tour of that first-run setup so nothing feels mysterious.

**What you'll learn:** what the runtime choices mean and how to change your mind later.

## Before you start

You'll need one of the following to give your agent a brain:

- **An API key** from a provider like OpenAI, Anthropic, OpenRouter, or another supported service. This is the fastest option — paste the key and you're live.
- **A local model** running via [Ollama](https://ollama.com). No key required; it runs entirely on your machine.
- **An Eliza Cloud account** if you want a managed provider that's designed for Milady specifically.

Don't have any of these yet? That's fine — start local or Cloud, then connect a provider later in Settings.

## Runtime Target

Milady separates **where the runtime lives** from **what language model powers it**. First-run setup asks where your agent should run.

| Option | What it means | When to pick it |
| --- | --- | --- |
| **Local** | The Milady runtime runs on this computer. Everything stays on your machine. | Almost everyone. This is the default. |
| **Remote** | The runtime lives at a custom URL you specify. | Self-hosting on a VPS, Docker host, or similar. |
| **Eliza Cloud** | The runtime is hosted by Eliza Cloud. No local install needed. | You want the simplest possible setup and don't want to manage a runtime. |

<Callout kind="tip">
Picking **Local** is the right answer for most people. You can switch later if you set up a server somewhere else.
</Callout>

## Identity

This is where you tell Milady what to call you and what to call the agent.

The default agent name is Milady. You can rename the agent later.

## Voice

Milady tries voice during first-run automatically. If speech recognition is not available in the renderer or microphone permission is denied, the setup stays on the same screen and you can keep typing.

## Provider

First-run setup does not force provider configuration before launch. If your selected runtime still needs a model provider, Milady sends you to Settings with a clear next action.

## Launch

After the target is ready, Milady opens the main interface: chat, the character surface, and Settings.

Total time is usually under a minute for Cloud or an already-installed local runtime.

## What about iOS and Android?

On phones, the first-run setup is the same: name, runtime target, launch. You can point a phone at a desktop running Milady with **Remote**.

## I want to change my mind

Every first-run choice is editable after the fact:

- **Character, name, avatar, voice** — Settings → Character
- **Provider** — Settings → Providers
- **Runtime target** — Settings → Runtime

There's no wrong first-run choice. Pick something, move on, change it when you want.
